## 2. 已确定的架构决策

### ADR-013-01：空间是逻辑容器，不是目录

原因：一个空间需要包含多个不同磁盘项目；把空间绑定目录会与项目工作区重复。结果：Space 无路径字段，Project 继续拥有唯一工作区根。

### ADR-013-02：任务独立于对话

原因：状态、截止日期和排序生命周期不同于消息历史。结果：Task 通过可空唯一 `main_conversation_id` 关联，不复制消息。

### ADR-013-03：资产是索引引用，不复制文件

原因：降低磁盘占用、避免版本分叉和删除风险。结果：删除资产索引绝不删除原文件，路径失效由扫描确认。

### ADR-013-04：V1.3 只用 SQLite FTS5

原因：本地、依赖少、适配 2G 显存/普通笔记本，不需要 GPU 或在线 Embedding。结果：不建向量字段和模型下载入口；中文通过确定性 unigram/bigram 增强。

### ADR-013-05：Watcher 只作为提示

原因：Windows 事件缓冲可能溢出并丢事件。结果：overflow 标脏并完整 reconciliation，完整扫描才是最终事实来源。

### ADR-013-06：每个工作负载独立 Native Context

原因：V1.2 全局可变 root 在 Agent 与索引并发时可能串项目。结果：Factory 创建 per-run/per-worker session，先完成 T02 再开发索引。

### ADR-013-07：文本索引上限与读工具一致

原因：复用已审计的 512 KiB 安全读取边界，避免新增大文件读取面。结果：更大文本只索引元数据，后续版本另行评审流式读取。

### ADR-013-08：任务 Agent 不自动完成任务

原因：一次模型回答不等于业务完成，自动更新会产生错误状态。结果：V1.3 由用户明确操作状态，模型不获得 task_write 工具。

### ADR-013-09：ViewModel 不使用第三方 MVVM 包

原因：当前项目依赖少，所需命令/通知范围有限。结果：自建小型 ObservableObject/AsyncCommand；若超过 400 行或出现重复再评审依赖。

### ADR-013-10：不自动 VACUUM

原因：大索引库 VACUUM 阻塞且产生临时磁盘占用。结果：只在满足空闲/比例/周期条件时提示用户，日常依赖复用空闲页与 checkpoint。

## 4. 变更控制

以下变化属于重大需求变更，必须暂停开发并更新整套文档：

- 一个项目支持多个工作区根。
- 允许跟随 symlink/junction。
- 支持工作区外文件、网络共享或可移动介质自动授权。
- 加入 PDF/OCR/Office/图片内容解析。
- 加入 Embedding、向量数据库或在线索引。
- 让模型写任务状态或自动完成任务。
- 应用退出后继续扫描。
- 将索引或任务同步到云端。

以下属于实现细节，可在不改变行为时调整，但必须记录：

- 类和文件名。
- UI 控件内部组合。
- SQL 查询执行计划优化。
- 不改变输出的哈希/分块性能优化。

## 5. 开发开始前无待定项

本需求包刻意给出默认值，不保留阻塞开发的“待产品确认”。若实际仓库或 Windows API 与合同冲突，Agent 必须提交证据并请求变更，不能静默选择另一行为。
