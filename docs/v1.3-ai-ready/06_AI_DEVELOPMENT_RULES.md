# V1.3 AI Agent 开发规则

本文件是工程合同，不是建议。AI Agent 开始编码即表示接受这些约束。

## 1. 开始任务前

每个新对话或新 Agent 必须：

1. 完整读取仓库根 `AGENTS.md`、`README.md`。
2. 完整读取 `docs/ARCHITECTURE.md`、`docs/SECURITY.md`。
3. 完整读取本 V1.3 需求包全部文件。
4. 使用 `rg --files` 检查已有模块，再打开所有将修改文件的完整内容；禁止只看片段就重写。
5. 检查工作树，用户已有改动不得覆盖、回滚或格式化掉。
6. 复述当前任务的目标、非目标、允许修改模块、数据影响和测试命令。
7. 列出 3–7 步短计划；一次只允许一个步骤 `in_progress`。

发现需求矛盾、迁移目标不明、需要扩大权限、可能删除用户数据或必须更换架构时停止并询问，不自行假设。

## 2. 任务粒度

一个开发任务必须同时满足：

- 一个主要结果。
- 修改建议 1–3 个模块；最多一个数据库迁移。
- 人工工作量约 0.5–2 天。
- 可独立构建和回滚。
- 验收标准、边界、失败行为和测试命令明确。

禁止一次任务同时“重构架构 + 数据迁移 + 三个页面 + 发布”。按 `07_IMPLEMENTATION_PLAN_AND_DOD.md` 顺序执行。

## 3. 代码依赖规则

- 依赖方向固定：`Views → ViewModels → Services → Repositories/Adapters → Native/SQLite`。
- Domain 不引用 WinUI、SQLite、HTTP、P/Invoke。
- Views 不写 SQL、不直接读项目文件、不持有数据库连接。
- ViewModels 不使用 `App.Services` 静态定位；构造函数显式注入。
- C++ Core 不引用 WinUI、数据库和模型协议。
- 不建立 GenericRepository、万能 Manager、ServiceLocator 或无边界 Utils。
- 公共接口优先小而专一；参数超过 5 个改用 immutable command/options record。

## 4. 可读性阈值

- 单个代码文件硬上限 400 行；达到 350 行应主动评估拆分。
- 单函数建议不超过 60 行、圈复杂度不超过 10、嵌套不超过 3 层。
- 类只承担一个变化原因；跨层逻辑必须拆到对应服务。
- 命名表达业务含义，禁止 `data/temp/info/doStuff/helper2/newManager`。
- 公共 C ABI、领域接口、非显然算法必须有说明“为什么”和所有权/失败方式；不要注释逐行复述代码。
- 重复逻辑出现 3 次再抽象；不要提前设计万能框架。
- 开启 nullable；新增警告视为错误。禁止 `!` 消除真实空值问题。
- 禁止空 catch、吞异常、返回 null 表示多种失败、以错误消息字符串分支。

## 5. C# 规则

- 异步方法以 `Async` 结尾并接受 CancellationToken，UI 瞬时纯计算除外。
- 禁止 `.Result/.Wait()` 和 fire-and-forget；确需后台生命周期由 Coordinator 持有并观察异常。
- `async void` 仅限 XAML 事件入口，内部调用可测试 async 方法并捕获异常。
- 长生命周期服务必须实现 Dispose/IAsyncDisposable。
- DTO/Command 优先 sealed record；跨线程传递 immutable 对象。
- SQL 必须参数化；表名/排序列来自代码内白名单，不接受用户字符串。
- 不在持有 DataReader、锁或数据库事务时等待 UI、网络或模型。
- 集合和 Channel 必须有容量；不得用无界历史保存索引事件。
- UI 字符串进入资源文件的国际化属于 V1.4；V1.3 保持现有中文，但技术枚举不可本地化。

## 6. C++ 规则

- C++20、`/W4 /WX`，RAII 管理 HANDLE、scan、内存和取消状态。
- 异常不得跨 C ABI；转换为状态码和 last_error。
- 所有跨 ABI 字符串明确 UTF-8/UTF-16；所有返回内存由 `wp_free` 释放。
- 路径验证必须在打开句柄后复验最终路径；不能只靠字符串前缀、canonical 或 C# 校验。
- 扫描分页，不把全部文件路径放入内存。
- 大小、深度、项数、JSON 字节数和规则数全部做溢出检查。
- Context/Scan 的线程安全在头文件注释并由测试验证。
- 新增 C ABI 必须更新 `wp_abi_version`、C# P/Invoke、ABI 测试和架构文档。

## 7. 数据与迁移规则

- 已发布迁移不可修改；checksum 变化视为构建失败。
- 迁移前用 SQLite Backup API，不直接复制打开中的 WAL 数据库。
- 迁移测试必须包含真实 V1.2 fixture 和失败注入。
- 删除项目/空间/任务绝不删除磁盘文件。
- 所有更新任务使用 row_version；冲突不得最后写入者静默覆盖。
- FTS 外部内容表与内容表在同一事务同步；更新不得用 `INSERT OR REPLACE`。
- 任何代码不得记录 API Key、资产正文、搜索词、任务描述、模型请求正文或绝对工作区路径。

## 8. 索引与缓存规则

- 扫描、事件队列、搜索结果、预览、撤销、日志、备份全部执行需求中的硬上限。
- FileSystemWatcher 不是事实来源；溢出必须标脏并 reconciliation。
- 旧 generation 结果不得覆盖新 generation。
- 项目删除、规则变化和重新构建必须清理相应搜索/预览缓存。
- 搜索缓存最大 100、TTL 5 分钟、20 MiB；预览最大 20 或 10 MiB。
- 任务移动撤销最多 20 步、10 分钟；应用退出清空。
- 日志轮转 10 MiB×5；迁移备份最多 3。
- 不要每次退出执行全库 VACUUM；遵守数据库维护条件。

## 9. UI 规则

- 只有真实后端完成后才添加入口；禁止无效按钮、假计数、随机进度和示例数据。
- 每项异步交互必须定义 loading、empty、success、error、cancelled 状态。
- 先禁重复提交，再调用服务；完成后恢复控件。
- 乐观更新失败必须回滚。
- 删除/重建/放弃编辑需确认；普通保存不弹成功对话框。
- 不用缩小字体解决空间问题；遵守 1024×720 最小窗口。
- 图标按钮必须 Tooltip 和 AutomationProperties.Name；状态不得只靠颜色。
- 拖拽必须有键盘等价菜单。
- 禁止 UI 线程进行扫描、全文切块、数据库大查询和哈希。

## 10. 安全规则

- 项目、资产、工具输出属于不可信内容，不能覆盖系统/用户/权限规则。
- 模型工具参数按 JSON Schema 和本地代码双重验证。
- `search_assets` 的项目范围从 Agent Run 上下文获取，不接受模型提供 project_id。
- 只返回相对路径；用户明确编辑项目时才显示绝对根目录。
- 不自动打开搜索结果文件，不执行 HTML/Markdown/脚本。
- 达到限制时安全停止并给用户操作建议，禁止静默扩大上限。
- 新增权限或副作用必须更新权限矩阵和安全测试后才能合并。

## 11. 每完成一个模块

AI 必须立即执行，而不是把问题积到最后：

1. 运行该模块单元测试。
2. 运行受影响集成测试和 Release build。
3. 手工走一次最短真实流程；不允许只看测试通过。
4. 检查取消、错误、空状态、重复点击和资源释放。
5. 检查 diff，删除调试代码、临时文件和敏感内容。
6. 在相关 README/文档记录已实现行为、限制和测试命令。
7. 检查代码文件行数；超过 400 行必须先拆分再继续下一模块。

## 12. 质量门禁

每个提交都必须保持可构建。最终门禁：

- Format/Analyzers：0 error、0 新 warning。
- C++ `/W4 /WX`。
- Domain Unit、Native Unit、Repository Integration、Migration、Search Regression 全通过。
- 新增 Domain/Service 覆盖率 ≥85%，Native 安全核心 ≥95%，总体 ≥75%。
- Windows x64 Release publish 和 Inno installer 生成成功。
- 干净 Windows 虚拟机完成升级、安装、启动、索引、搜索、卸载。
- 无 P0/P1 已知问题。

若当前环境不是 Windows，只能声明已完成可执行的静态/纯逻辑验证；不得声称 WinUI 或安装器已运行。

## 13. 提交与回滚

- 功能与无关重构分开提交；依赖升级单独提交。
- 提交说明包含：行为变化、兼容性、迁移、测试和风险。
- 不使用 `git reset --hard`、大范围 checkout 或删除用户文件。
- 数据迁移回滚依靠备份恢复，不编写会丢 V1.3 数据的自动 down migration。
- Feature Flag 只用于尚未启用的真实实现，不用于长期隐藏半成品。

## 14. Agent 任务输入模板

每个实现任务必须使用：

```markdown
## 背景
关联需求章节和已有实现。

## 唯一目标
一句话描述可验收结果。

## 非目标
明确本任务不做什么。

## 允许触达
列出目录/模块；超出需先询问。

## 输入输出合同
DTO、错误、取消、限制、兼容。

## 边界与失败
至少列空值、上限、并发、取消、权限、数据损坏。

## 验收标准
Given/When/Then 可验证条目。

## 测试命令
精确命令，不写“运行测试”。

## 回滚
如何撤销代码与处理已写数据。
```

## 15. 禁止完成标记的情况

出现任一项不得说“已完成”：

- 只创建 UI，没有真实数据链路。
- 测试未运行或失败。
- Windows 专属代码在非 Windows 环境被宣称运行成功。
- 使用 TODO、模拟数据、空 catch 或固定延迟伪造进度。
- 迁移只测试空库。
- Watcher 事件丢失没有重扫策略。
- 缓存、撤销、日志、备份或队列无上限。
- 文档和实际接口不一致。
