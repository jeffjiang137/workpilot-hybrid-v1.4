## 2. 冻结架构决策

### ADR-1401：C++ 核心 + C# WinUI 3

决定：沿用 V1.3 混合架构。C++ 负责不可绕过的 OS/安全边界，C# 负责 UI、应用编排和协议。  
理由：保留原生 Windows 能力与安全边界，同时控制 UI 开发复杂度。  
后果：必须维护窄 C ABI 和双语言测试；禁止在两侧复制规则。

### ADR-1402：技能为纯声明式包

决定：V1.4 技能只含 manifest、Markdown、模板和静态资源，不执行代码。  
理由：避免把技能安装变为任意代码执行和供应链系统。  
后果：需要代码能力时必须通过内置连接器或显式 MCP，并独立授权。

### ADR-1403：连接器与 MCP 分离

决定：连接器是随应用发布的受控适配器；MCP 是外部不可信服务。二者共享能力/权限/审计抽象，但生命周期与信任不同。  
后果：UI 在同一“连接”模块展示，但不得用一个模糊 provider 接口抹平安全差异。

### ADR-1404：MCP 稳定版 2025-11-25

决定：完整目标为 `2025-11-25`，有限兼容 `2025-06-18`，拒绝其他版本。  
理由：避免随草案变化；让兼容范围可测试。  
后果：sampling、roots、durable tasks 不纳入 V1.4。

### ADR-1405：本地确定性技能选择

决定：使用规范化词法评分，不依赖 embedding/云服务/使用历史。  
理由：离线、隐私、可解释、可复现。  
后果：语义召回有限；未来更换算法必须版本化并保留快照中的算法版本。

### ADR-1406：能力授权绑定 Schema 哈希

决定：授权绑定内部 capability ID + schema_sha256，不只绑定名称。  
理由：防止同名工具改变参数/副作用后继承旧授权。  
后果：安全相关 Schema 变化需用户复核。

### ADR-1407：不声称 MCP 子进程沙箱

决定：本地 stdio 以当前用户权限运行，使用路径/宿主限制、显式确认和 Job Object 管理，但不宣传为沙箱。  
理由：V1.4 没有完整 AppContainer/虚拟化隔离。  
后果：UI 必须清楚提示用户只添加可信程序。

## 3. 开放但不阻塞 V1.4 的决策

| 主题 | V1.4 默认 | 后续评估触发条件 |
|---|---|---|
| 团队策略同步 | 仅本机 | 有账号/组织后端后 |
| 技能签名 | 展示包哈希，不建 PKI | 上线技能市场前 |
| stdio AppContainer | 不支持 | 可兼容 server 清单与 broker 设计完成后 |
| 更多连接器 | GitHub/Notion | 统一契约稳定且有明确需求后 |
| 语义技能选择 | 不支持 | 有本地 embedding、隐私与确定性方案后 |
| MCP sampling/roots/tasks | 不支持 | 稳定规范、产品场景和权限模型完成后 |

## 4. 非目标防漂移清单

编码 AI 不得顺手实现：

- 技能在线市场、自动更新、脚本 runner、动态 DLL 插件。
- 任意“通用 HTTP 请求”连接器。
- 自动安装 Node/Python/MCP server 或从网络下载 executable。
- 永久允许外部写入或绕过每次确认。
- 把 GitHub/Notion 完整响应持久化或全文索引。
- 在 MCP prompt 中接受 system role。
- 未列出的 OAuth grant、客户端 secret 收集或 token exchange。
- 用 WebView 嵌入任意 MCP 页面。

## 5. 变更流程

任何冻结项变更必须：

1. 新增 ADR，写问题、候选、决定、安全/迁移/兼容影响。
2. 更新 PRD 需求 ID、算法、数据模型、QA 和追踪表。
3. 明确从哪个小版本生效，不修改历史快照解释。
4. 由人工审查安全边界；AI 不得自行批准降低限制。

## 6. 实现状态词典

- `NotStarted`：没有产品代码。
- `InProgress`：部分代码或测试，不能对用户声称可用。
- `Implemented`：任务 DoD 通过。
- `ReleaseReady`：所属版本全部门禁通过并完成包验证。

页面 shell、interface、mock、demo 均不等于 Implemented。
