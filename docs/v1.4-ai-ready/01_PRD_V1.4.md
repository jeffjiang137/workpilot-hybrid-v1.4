# PRD：专家、技能、连接器与 MCP

## 1. 产品问题

V1.3 能管理本地工作并进行 AI 对话，但所有会话几乎共享同一组能力，用户无法回答以下问题：

- 当前对话以什么角色、规则和专业知识运行？
- 为什么某项技能被使用？它能访问哪些数据？
- 哪个外部账号正被调用？会不会写入或删除内容？
- MCP 服务暴露了什么工具，是否可信，谁批准过？
- 专家配置变化后，正在执行的任务是否会被悄悄改变？

V1.4 的目标是把“可扩展能力”变成清晰、可选择、默认拒绝、可撤销、可审计的产品能力。

## 2. 目标用户与核心场景

### P1：知识工作者

创建“产品专家”，绑定 PRD 技能与 Notion 只读连接，选择空间后让 AI 汇总资料。用户能看到当前启用能力及来源。

### P2：研发负责人

创建“研发专家”，绑定 GitHub 与本地 MCP 服务，查询 Issue、代码资源，并在明确确认后创建 Issue 或评论。

### P3：安全敏感用户

在安全中心查看各专家、空间、连接账号和 MCP 工具的授权，撤销会话授权，停用异常服务并导出脱敏审计记录。

### P4：技能作者

按公开包格式制作纯文本技能，导入后获得确定的验证结果；失败时定位到文件、JSON Pointer 和规则编号。

## 3. 产品原则

1. 默认拒绝：新连接、新 MCP 服务、新增工具都不会自动获得写权限。
2. 显式来源：能力名称必须带来源；不得把外部工具伪装成内置工具。
3. 快照执行：一次运行使用不可变的专家修订与能力快照。
4. 最小披露：只向能力提供完成调用所需的参数和上下文。
5. 可解释：技能激活、风险等级、确认原因和失败原因均可查看。
6. 可恢复：禁用、重连、撤销、重试都不得破坏已有任务或会话。

## 4. V1.4.0：专家与技能

### 4.1 专家需求

| ID | 必须需求 | 验收摘要 |
|---|---|---|
| EXP-001 | 创建、复制、编辑、归档专家 | 重启后保留；内置专家不可删除，只能恢复默认 |
| EXP-002 | 每次保存生成不可变修订 | 旧会话仍引用旧修订；新会话使用最新修订 |
| EXP-003 | 绑定 0–20 个技能并排序 | 顺序持久化；超限被 UI 和服务层共同拒绝 |
| EXP-004 | 配置模型偏好、系统指令、工具策略 | 模型不可用时展示替代选择，不静默切换 |
| EXP-005 | 在新建任务/对话时选择专家 | 对话标题区持续显示专家和修订状态 |
| EXP-006 | 提供“试运行”沙盒 | 不执行外部写操作；展示编译后的能力摘要而非泄露完整系统提示 |

专家名称 1–60 字符，描述 0–400 字符，系统指令 0–32,000 字符。保存时去除首尾空白，但保留内部换行。空名称、控制字符和全空白名称拒绝。

### 4.2 技能需求

| ID | 必须需求 | 验收摘要 |
|---|---|---|
| SKL-001 | 从 `.zip` 导入声明式技能 | 先验证、再预览、用户确认后原子安装 |
| SKL-002 | 查看清单、指令摘要、版本、哈希、来源和权限声明 | 所有字段来自已验证包，不执行包内文件 |
| SKL-003 | 全局安装、按专家启停 | 停用不删除；运行中的快照不受影响 |
| SKL-004 | 显示技能激活原因 | 显示“固定”“别名命中”“标签命中”等证据 |
| SKL-005 | 更新与回滚一个已安装版本 | 不联网自动更新；保留至多 3 个版本 |
| SKL-006 | 卸载 | 被专家引用时先显示影响，确认后解除绑定并卸载 |

V1.4 不允许技能包含 DLL、EXE、脚本、宏或包管理器安装步骤；技能不能自己注册可执行工具，只能指导模型使用已经授权的能力。

### 4.3 V1.4.0 发布验收

- 创建专家并绑定两个技能后，可开始对话，标题显示专家名称。
- 修改专家并保存后，旧会话标记“使用历史修订”，行为快照未变化。
- 恶意 ZIP 路径穿越、符号链接、压缩炸弹、脚本文件均被拒绝且没有写入最终目录。
- 技能自动激活结果在相同输入和相同安装集下完全确定。
- 不配置专家时仍可使用 V1.3 默认助手。

## 5. V1.4.1：原生连接器

### 5.1 通用需求

| ID | 必须需求 | 验收摘要 |
|---|---|---|
| CON-001 | 连接账号、测试、重连、禁用、删除 | 删除先撤销引用；秘密从保险库移除 |
| CON-002 | 按空间启用，再按专家允许 | 两层都允许才进入能力目录 |
| CON-003 | 显示账号身份、权限范围、最近成功/失败 | 不显示完整 token，不在日志保存响应正文 |
| CON-004 | 统一超时、分页、限流、重试、熔断 | 算法按协议文档实现并具时钟可控测试 |
| CON-005 | 操作具有稳定 ID、输入 Schema 和风险等级 | 模型显示名变化不改变策略绑定 |
| CON-006 | 连接健康诊断 | 区分认证失败、限流、网络、服务端和策略拒绝 |

### 5.2 GitHub 内置连接器

V1.4.1 只读操作：

- `github.search_repositories`
- `github.get_repository`
- `github.list_issues`
- `github.get_issue`
- `github.list_pull_requests`
- `github.get_pull_request`
- `github.get_file_text`

V1.4.2 写操作：

- `github.create_issue`
- `github.add_issue_comment`

限制：单次文件读取 1 MiB；单次列表最多 500 条；私有仓库只有在 token 本身允许且空间策略允许时可见。写操作每次确认，V1.4 不提供“永久允许”。

### 5.3 Notion 内置连接器

V1.4.1 只读操作：

- `notion.search`
- `notion.get_page`
- `notion.get_database`
- `notion.query_database`

V1.4.2 写操作：

- `notion.append_page_blocks`

限制：返回内容转换为结构化纯文本；未知 block 类型保留类型占位，不丢弃整个页面；单次结果正文上限 20,000 字符。写入前预览目标页面、追加块数和纯文本摘要。

### 5.4 V1.4.1 发布验收

- token 写入后，数据库搜索不到其全文；删除账号后 DPAPI 密文文件同步删除。
- 未启用空间或未授权专家均无法看到连接器工具。
- 连续故障触发熔断，UI 可区分“服务故障”与“凭据过期”。
- 429 读取请求按策略退避；写请求绝不因普通网络失败自动重放。

## 6. V1.4.2：MCP 与安全治理

### 6.1 MCP 服务需求

| ID | 必须需求 | 验收摘要 |
|---|---|---|
| MCP-001 | 添加本地 stdio 服务 | 只接受绝对可执行路径与参数数组，不经过 shell |
| MCP-002 | 添加 Streamable HTTP 服务 | 默认 HTTPS；逐跳校验重定向和目标地址 |
| MCP-003 | 完成 initialize/initialized 生命周期 | 协议不兼容时停止并给出可操作错误 |
| MCP-004 | tools/list、tools/call | 本地风险分类覆盖服务端 annotations |
| MCP-005 | resources/list/read 与 templates | 读取大小、类型、页数均有上限 |
| MCP-006 | prompts/list/get | 预览后才插入对话，内容按不可信输入处理 |
| MCP-007 | OAuth 2.1 + PKCE S256 | state、资源指示器、元数据发现和 token 保护完整 |
| MCP-008 | 目录刷新、listChanged、进度、取消 | 防抖、有界并发，断线后显示陈旧状态 |
| MCP-009 | 停止、重启、禁用、删除 | 本地进程随 Job Object 结束，无孤儿进程 |

### 6.2 写操作与安全中心

- 写入、删除、执行、凭据、资金或未知副作用操作默认为高风险。
- 确认对话框展示来源、账号/服务、目标、参数摘要、潜在影响和授权范围。
- 安全中心支持按空间、专家、来源、风险、结果和时间筛选审计。
- 会话授权在应用退出、专家修订变化、连接重连、工具 Schema 变化或 8 小时后失效，以最早者为准。
- 服务声明的 `readOnlyHint` 等 annotations 只能作为参考，不能降低本地风险等级。

### 6.3 V1.4.2 发布验收

- stdio 服务输出非法 JSON、超大消息、协议日志混入 stdout 时安全失败，不导致客户端崩溃。
- HTTP 服务指向私有地址、云元数据地址或 HTTPS 降级重定向时被阻止；显式本地模式只允许 loopback。
- OAuth 回调 state 不匹配、PKCE 非 S256 或 token audience/resource 不匹配时失败并清理临时状态。
- MCP 工具名称冲突时使用稳定命名空间，策略不会串绑。
- 高风险调用取消后未发送请求；完成后产生脱敏审计记录。

## 7. 非功能需求

| 类别 | 指标 |
|---|---|
| 启动 | 未启用 MCP 时，V1.4 相对 V1.3 冷启动 P95 增量 ≤ 250 ms |
| 列表 | 1,000 个能力的虚拟化列表滚动无明显掉帧；搜索响应 P95 ≤ 150 ms |
| 连接 | 单账号并发 ≤ 4；全局外部调用并发 ≤ 12；等待队列各 ≤ 100 |
| 稳定性 | 单个连接器/MCP 崩溃不得导致主进程退出 |
| 资源 | 单 MCP 消息 ≤ 4 MiB；单结果注入模型 ≤ 20,000 字符 |
| 隐私 | 日志、审计、崩溃报告不包含秘密、完整提示、完整响应正文 |
| 可访问性 | 100%/125%/150%/200% 缩放可用，主要流程全键盘操作 |
| 本地化 | 所有用户可见文本进入资源文件，首发简体中文和英文键位友好 |

## 8. 指标与遥测

默认只保存在本地：专家创建数、技能验证结果计数、连接状态、MCP 初始化耗时、调用结果类别和风险确认结果。禁止记录用户名、仓库名、页面标题、查询、提示、参数、响应正文、URL 查询串和 token。

## 9. 明确非目标

- 技能商店、在线自动更新、技能脚本执行、第三方 DLL 插件。
- MCP server 托管、MCP sampling、roots、durable tasks。
- 无人值守高风险自动化、永久允许写操作、团队云策略下发。
- Linux/macOS 客户端、移动端、浏览器扩展。
- 用连接器替换完整 GitHub/Notion 客户端。
